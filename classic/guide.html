PacketLab field manual

Learn networks by breaking them.

Build a topology, create traffic, introduce a failure, and use the evidence to explain what happened. This guide turns the simulator into a sequence of focused experiments.

5 labsBuild → Configure → Generate → Diagnose → Compare

Each lab can be completed with the default diamond topology in about 10 minutes.

Your experiment path

Change one variable at a time. Run long enough to see a stable pattern, then use the event trace and metrics to support your conclusion.

LAB 01

Build the topology

Add hosts, routers, and switches. Connect nodes, then inspect the simulated IPv4 interfaces and forwarding tables.

LAB 02

Shape the links

Change bandwidth, propagation delay, loss probability, and queue capacity. Predict the bottleneck before running.

LAB 03

Generate traffic

Compare independent UDP-like datagrams with a TCP Reno transfer. Watch throughput, delay, and congestion window.

LAB 04

Cause a failure

Inject congestion or disable a selected link. Recompute routes and observe which packets drop during the transition.

LAB 05

Compare the evidence

Export traces as CSV and topologies as JSON. Change one parameter, repeat the run, and compare outcomes.

CHALLENGE

Find the tipping point

Increase the offered load until delay rises sharply. Explain the relationship between arrival rate, service rate, and queue growth.

Model boundaries

PacketLab reproduces selected observable mechanisms in virtual time. It is an educational simulator, not a standards-compliant network stack.

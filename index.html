Experiment guide

Student lab
1. Build: Add hosts, routers, and switches. Connect nodes and inspect their simulated IPv4 interfaces and route tables.
2. Configure: Change link bandwidth, propagation delay, loss, and queue capacity.
3. Generate: Create independent UDP-like datagrams or a simplified TCP Reno byte transfer.
4. Diagnose: Inject congestion or disable a link; observe route changes and drops.
5. Compare: Export CSV traces and JSON topologies to reproduce experiments.
Educational IP and TCP models, not a full TCP/IP stack: IPv4 addresses, interface routes and TTL are simulated; TCP Reno includes handshake, cumulative ACKs, congestion window and retransmission. No ARP, Ethernet MAC learning, real checksums or production sockets.

What this simulator implements vs a full protocol stack

Model boundaries

The teaching implementation reproduces selected observable protocol mechanisms using virtual time. It is not a standards-compliant implementation and does not exchange real packets with operating systems or networks.

AreaSimulated hereFull IP/TCP protocol implementation
IPv4IPv4 source/destination, protocol number, TTL, interfaces, auto-addressed subnets, /32 routes and longest-prefix lookup.Actual binary headers and checksums, fragmentation/reassembly, full ICMP, IP options and standards-based edge cases.
RoutingDijkstra/Bellman–Ford calculate IPv4 next hops; routing updates on topology/configuration changes.Real routing-protocol exchanges, convergence timers, ECMP, policy routing, administrative distance and failure recovery.
SwitchingSwitch nodes relay packets across shared simulated IPv4 subnets using logical forwarding.Ethernet frames, MAC learning, ARP, broadcast/multicast, VLANs, spanning-tree behavior and real NICs.
UDP-like trafficIndependent connectionless IPv4 packets with configurable rate, size, loss and queueing.UDP ports, header/checksum validation, datagram sockets and full application-layer behavior.
TCP RenoThree-way handshake, byte sequence numbers, cumulative ACKs, receiver buffering, cwnd/ssthresh, slow start, Reno additive increase and loss-triggered retransmissions, RTT/RTO estimates, FIN/ACK close.Production TCP state machine, simultaneous connections/open/close, SACK, window scaling, delayed ACK, persist/keepalive, MSS negotiation, timers and all RFC edge cases.
ExecutionDeterministic discrete events, finite FIFO queues, virtual link delay/loss and packet tracing.OS socket implementation, real I/O, hardware interrupts, drivers, kernel scheduling and physical networks.

This distinction matters: simulating a mechanism means reproducing its selected behavior for experiments; a full protocol implementation must correctly process interoperable on-wire formats and all required protocol states and corner cases.
